# 每日台股分析工具完整規劃書

版本：0.9.1；日期：2026-10-16；狀態：全高帳號側欄與右側標題已完成；已實測官方 Codex 真實用量；支援雙擊 HTML 與使用者／Codex 兩套接埠。分析功能的真實帳號授權及 AI 查詢仍待使用者完成。完整交易功能仍依階段開發。

## 1. 目標與已確認決策

市場為台灣上市、上櫃股票；每交易日台北時間 12:00 截止資料，產出 0～3 檔；當日手動買進，下一交易日必須出清，不當沖、不串券商下單。保存推薦、模擬及實際結果，用多日樣本驗證策略。目前不使用任何付費服務。技術以 TypeScript、Node.js、React 為主；PostgreSQL 延至資料量與部署需求明確後採用，先使用本機 JSON，避免安裝負擔。

## 2. 免費版本界線

免費不等於可取得全市場即時或歷史分鐘行情。收盤研究接受手動匯入合法取得的完整日 K，不冒充 12:00 推薦。v0.2 新增 ChatGPT 手動／排程 AI 市場查詢；其網路摘要不視為全市場數據匯入。v0.5.0 已加入官方收盤快照、自動初選及部分盤中報價；仍不含持續盤中監控、完整回測、全市場技術掃描與內外盤。免費盤中來源驗證失敗時，技術選股保持關閉。無付費 API 備援，不自行購買服務或點數。

## 3. 職責與目錄

`server/index.ts` 負責 HTTP 與輸入驗證；`server/store.ts` 負責序列化寫入與暫存檔替換；`server/strategy.ts` 僅計算策略；`server/auth.ts` 負責官方 OAuth 與續期；`server/ai.ts` 負責帳號模型清單與完整串流；`server/jobs.ts` 負責工作狀態與排程；`shared/model.ts` 定義契約；`src/QueryPanel.tsx` 負責帳號與查詢介面，其餘 `src/` 負責研究與交易；`doc/` 管理規格與版本；`data/` 保存使用者資料。單一專案，不建立微服務；策略不依賴供應商格式。

## 4. 股票範圍與資料品質

目標股票池為上市、上櫃普通股，不含 ETF、權證、興櫃與特別股。v0.1 四位數代碼檢查不能證明商品種類，匯入者須自行確認；v0.5.0 自動行情以官方上市櫃公司主檔對應四位代碼；手動匯入仍需自行確認商品。未來必須處理歷史上市下市名單、交易日曆、停牌、處置、上市初期、公司行動、資料延遲及授權。自動行情已核對 JSON、欄位、日期與單位，但仍不能保證來源無誤或資料完整。不同股票資料截止不一致不得視為全市場掃描。

## 5. 指標與研究策略 v0.1

使用截至研究日期的完整日 K，至少 60 筆；SMA5、SMA20；KD 使用 9 筆 RSV，K、D 各以 2/3 舊值加 1/3 新值，初始 50，最高最低相同時 RSV=50；MACD 使用 EMA12、EMA26、訊號 EMA9，EMA 初始取首筆收盤價，訊號初始 0。需要足夠暖機，與券商顯示值可能不同。量比使用當日量 / 前 20 筆平均量，不含當日。

五條件各一分：收盤大於 SMA20、SMA5 大於 SMA20、K>D 且 K<80、MACD 大於訊號、量比大於 1.2。至少四分且成交量正值才列入；分數降序、代碼升序，最多三檔，允許零檔。這是待驗證的研究基準，不是經證明有效的策略；尚未設金額流動性或產業風險門檻，不可直接作為正式買進建議。暫不計算 K 線型態及內外盤，不能宣稱已納入。

## 6. 正式盤中流程（尚未實作）

交易日曆決定是否執行；以 Asia/Taipei 12:00 截止資料。日線特徵僅取前一交易日以前已完成日 K；盤中訊號獨立計算，不得混用當日收盤。固定資料快照後，資料品質、流動性、風險過濾，再排名。結果需顯示資料時間、發布時間、涵蓋檔數、排除原因、有效買進區間與取消條件。資料不足、失敗、零推薦是不同狀態。重試不得重複發布。

## 7. 交易與退出

由使用者手動買賣，系統僅提示與紀錄。正式策略為隔日依停損、停利或技術訊號提前出場，未觸發則到約定時間出清。買進窗口、最晚出場時間、訊號監控頻率、停損停利與優先順序均待使用者確認，不隨意代填成正式規則。停牌、跌停或無量導致無法出清時，記錄未平倉及原因，不虛構成交。v0.1 僅驗證賣出日期晚於買入，不具交易日曆，不能驗證是否真為下一交易日；也不提供自動通知或持倉修改。

實際交易與標準模擬交易應分開，正式資料需關聯推薦 ID、策略版本、股數、成交價、時間、費稅及未成交原因。v0.1 為簡單手動交易表，尚未建立推薦關聯，無法當成完整策略歸因報表。費稅由使用者填寫實際總額，未自動套用稅率。

## 8. 風險與資金（正式啟用前必填）

總資金、單筆與單檔上限、最多持倉、產業集中上限、可接受損失、整張或零股、最低成交金額與價格追高限制。評分不是成功機率；不以 AI 生成機率。買不到可放棄，不要求每天三檔。

## 9. 回測與每日驗證（尚未實作）

不能以今日收盤訊號模擬今日較早買進。若採完整日 K，最早只能在訊號已知後的可交易時點買入，且這屬另一種策略；中午策略必須有當時盤中歷史。信號產生與下單成交至少分開，包含滑價、手續費、交易稅、未成交、漲跌停及公司事件。不能只用目前仍上市股票回測歷史。訓練、調參與最終測試以時間分開，採時間推進驗證。

每筆記錄成本後報酬、持有期及是否實際成交；整體觀察樣本數、平均盈虧、勝率、盈虧比、最大回撤、成交率與同期間基準。每日結果用來累積證據，不能以一天輸贏判定策略有效。不捏造回測數據；資料不足時輸出不可評估。新版本先比較與模擬追蹤，再由使用者決定是否正式採用。

## 10. AI、登入與費用

v0.2 採官方 Sign in with ChatGPT 的本機個人專案流程：瀏覽器開啟官方登入頁，使用 loopback callback、PKCE、state、nonce、簽章／issuer／audience／expiry 驗證；不收集密碼、不擷取瀏覽器 Cookie。登入身分與額度授權分開，未取得 chatgpt.tokens.use.direct 不呼叫分析。可保存多個帳號註冊識別，但一次只啟用一個；切換帳號需重新驗證。v0.3.6 起 Access／refresh／ID token 以 Windows DPAPI CurrentUser 加密保存，重啟自動還原；刷新序列化、登出嘗試撤銷續期授權，未確認撤銷時提示使用者至 ChatGPT 設定中斷。

模型清單取自帳號實際回傳，不硬編號稱可用的模型。查詢走官方 Responses 端點，store=false、stream=true，只在 response.completed 且有完整文字後保存成功。網路查詢要求工具執行及引用來源；無引用、中斷、額度不足或模型不支援均記失敗，無付費備援。AI 回覆以純文字呈現，來源另以 HTTP(S) 連結顯示，不執行回覆中的 HTML 或程式。

使用者問題與勾選的最新收盤研究會送給 OpenAI；不自動附加成交明細。AI 提示要求資料時間、區分證據與推論、不得捏造數值。這些限制無法保證模型永不出錯，使用者仍需核對引用。ChatGPT 方案資格及模型功能以實際登入與請求結果為準，不能宣稱已為此帳號驗證。查詢可消耗使用者授權的訂閱額度或既有點數，請在 ChatGPT 設定限制用量；工具不購買點數或設定 API 金鑰。新增付費來源與雲端服務前必須另行取得同意。

## 10.1 手動查詢與平日排程

手動查詢按下按鈕後建立工作，回傳工作 ID，頁面每五秒更新狀態。每次最多一個工作，避免重複送出；保留問題、模型、網路查詢選項、附加研究 ID、觸發方式、帳號識別、開始／結束時間、引用與錯誤。關閉網頁不取消正在執行的本機工作。

排程預設停用、台北時間 12:00、週一至週五；使用者勾選並儲存後才啟用。每三十秒檢查，每個選定平日最多嘗試一次，執行前持久保存日期與工作狀態。每天的五分鐘窗口外標記 missed，不補跑過期查詢；同日重啟、修改時間或失敗均不自動重試。若需重試，按手動查詢。服務重啟時，未完成工作改標 interrupted。電腦關機／睡眠或服務關閉時不執行，也無法記錄已完全錯過的歷史日期；恢復後只評估當天，不宣稱已完整追蹤停機期間。

排程綁定儲存時的帳號，換帳號不自動扣新帳號額度，需重新儲存；登出會停用排程。正式交易日曆尚未整合，因此目前是平日市場查詢，休市平日仍可能查詢，不是交易日專用排程，也不會產生股票買賣指令。瀏覽器不需常開，但本機 Node.js 服務與網路必須可用。這不是雲端網站，不能在使用者電腦關機後繼續執行。

## 11. 保存、隱私與版本

目前行情依市場、代碼、日期唯一；相同資料重匯跳過，衝突拒絕。研究保存時間、截止日、策略版本、篩選數值與理由；資料追加後重跑可能因補漏改變，正式版須增加獨立資料集版本與快照雜湊。策略變更須升策略版本並更新 CHANGELOG，應用 v0.2 不變更研究策略 eod-research-0.1.0。資料庫新增 queries、schedule 與非憑證的 identity；舊資料讀取時補上預設欄位。禁止提交 data 或金鑰。此工具只有單一 Windows 使用者／單一後端程序的本機邊界，不提供多租戶帳號資料隔離；不可直接公開上網。正式多人服務需獨立授權、PostgreSQL、驗證與備份還原測試。

v0.3.1 帳號側欄：帳號選擇、登入登出、額度授權狀態及 Codex 用量置於左側，預設展開，使用者可收合／展開；右側為查詢、排程、結果與既有研究及交易內容。收合採隱藏保留元件狀態，不重設表單；頁面重新載入預設展開，不額外儲存偏好。窄螢幕上下排列，側欄取消固定定位。手動驗收涵蓋預設展開、鍵盤可用按鈕、收合後右側加寬、輸入保留、手機無溢出。

v0.3.0 帳號用量：參考使用者指定的 AiUsageDashboard 安裝包，唯讀查看其 README 與組件中的介面名稱，確認採官方 Codex App Server；未執行該 App、未複製其帳號或憑證。新增 server/usage.ts，以本機官方 CLI 執行 initialize、initialized、account/read、account/rateLimits/read，絕不建立 thread／turn，也不執行登入登出、重置額度、購買或通知他人等操作。CLI 沿用自己的登入狀態，不將憑證回傳前端。從 PATH 或官方 Windows 安裝目錄解析執行檔，也可透過伺服器環境 CODEX_EXECUTABLE 指定；HTTP 不接受任意執行檔路徑。只回傳經驗證的用量欄位，stderr 與 RPC 原文不寫入應用日誌。

用量資料只在服務記憶體快取；v0.3.7 起分析登入成功或還原登入後自動啟用查詢，之後每分鐘更新，並行請求共用同一次讀取。逾時或格式錯誤時清除數值並呈現原因，不能把舊資料或不存在的週期標成剩餘 100%。以官方 usedPercent 計算 100-usedPercent，週期依 windowDurationMins 顯示，resetsAt 從 Unix 秒數轉台北時間。多個額度群組逐一顯示，不假設第一個一定是五小時。點數僅在服務回傳時顯示。

用量卡是本機 Codex 帳號的唯讀狀態，與第三方應用分析登入可能是不同帳號／工作區或不同限制。顯示來源帳號與方案；若與分析登入 email 不同則明確提示，email 相同也不宣稱工作區或應用上限完全相同。目前不在介面修改官方限額，不以查詢次數估算帳號剩餘額度。

## 10/16 新增規劃：每日正式分析與隔日驗證（待開發）

### 目標及不變條件

每天固定分析時點、資料快照與策略版本，產生最多三檔條件式候選；保存不可覆寫的正式紀錄，下一個實際交易日資料齊備後自動檢驗。參考報價不視為已成交，不把條件通過改稱保證可立即買進。現有查詢紀錄繼續保留；此節為規劃，尚未實作。

### 職責分離

- 每日紀錄：鎖定分析日、query ID、發布時間、資料截止、快照雜湊、策略與參數版本、模型及範本版本、候選、完整排除原因、參考價與時間及價格種類。
- 價格計畫：由固定版本規則產生參考買價、取消條件及出場基準；AI 解釋，不從自由文字擷取成交價。最近成交與最佳賣價分開，不將最佳賣價視為成交保證。
- 驗證：取得經核對的下一交易日行情及來源，按預先鎖定的規則評估；與 AI 查詢分開，不因驗證再次消耗 AI 額度。
- 實際交易：使用者填入真實成交時間、股數、價款與費用，關聯每日候選 ID；模擬與實際分開。
- 改進：產出失敗歸因及版本比較，舊策略保留；不根據隔日輸贏直接修改正式規則。

### 一日一份正式結果與重查

同日、同策略版本保留一份正式主紀錄，首次符合發布條件者鎖定。零檔也是有效紀錄；AI 失敗、錯過時間、資料不足獨立保存，不冒充正常零候選。盤後分析使用不同用途與預定買進日，不能回填為當日盤中推薦。重查產生 revision 或補充紀錄，顯示原正式版及新資料時間，不覆寫；改策略建立新版本。分析使用資料必須在發布前已取得，驗證不得使用發布前不可能知道的數據。固定快照的程式分類需一致，AI 敘述不要求逐字一致。

### 驗證契約與尚待確認項目

先確認採雙軌（自動驗證市場走勢、真實交易另填）或僅真實成交。若做模擬，必須在發出名單時鎖定進場、出場、費稅、滑價、有效時間與未成交規則，不能看到隔日結果再挑選出場價。日線低點碰到限價不能證明發布後成交；隔日同根日 K 同時碰停利停損時，缺分時資料須標為路徑不明，不任選有利結果。只有日線時，先做收盤方向與參考價變化的前瞻驗證，不能稱完整交易回測。

下一交易日須依交易所日曆與臨時公告判定；無法確認、停牌、資料未到、公司行動或無法出清時分別標記，不能套用明天或判成選股錯誤。結果最早在對應資料實際可用後評估；服務休眠或關閉後，下次啟動可補驗既有紀錄，不補發過期買進名單。重試以每日紀錄 ID 及驗證版本去重。

### 顯示與驗收

獨立每日驗證頁：分析日、正式版、股票、技術條件、參考價與時間、次交易日、驗證狀態、方向、原始價差、實際／模擬成本後結果及失敗原因；報價過期、未成交與未平倉不能顯示零報酬。統計須列總分析日、零候選日、候選數、可驗證數、缺資料、未成交、勝負與每檔／每日兩種口徑；未足樣本不稱有效策略。

### 改進流程

先分類資料缺漏、過期報價、無法成交、訊號反轉、成本侵蝕、事件風險及持有時間不合；再對單一原因提出新策略版本。用一段歷史建立規則，另一段未用資料檢驗，之後用新交易日持續驗證。所有版本用相同日期、股票範圍、成本與成交假設比較，保留失敗樣本及零候選日。新版本先試行，不自行改動現行策略；不得刪除虧損紀錄或捏造回測。
